# Fink! Infrastructure Development Guide

## 1. 프로젝트 목적

Fink!는 금융기업의 내외부 업무 시스템과
보안 접근제어를 모의 구현하는 교육 프로젝트이다.

기존 AWS 및 VPN 기술을 활용하며,
실제 금융기관용 보안 엔진을 직접 개발하지 않는다.

## 2. 작업 범위

- 작업 브랜치: hyunmin
- 담당 영역: AWS 네트워크 및 보안 인프라
- 작업 경로: infra/
- 기존 팀원 코드는 읽기 전용으로 확인한다.
- 팀원의 소스코드와 서비스 설정을 수정하지 않는다.
- 다른 브랜치를 조회하거나 수정하지 않는다.
- 승인되지 않은 기능은 구현하지 않는다.

## 3. 개발 원칙

- 작업 전 README.md와 ROADMAP.md를 확인한다.
- 기존 구현과 최종 설계 목표를 구분한다.
- README.md에 기록한 사용자 승인 아키텍처 방향을 유지한다. 세부 설계, 팀 최종 합의, 구축 승인은 각각 확인한다.
- 최신 API 명세서와 DB 정의서를 참고한다.
- API 검토 문서의 제안과 팀에서 확정한 사항을 구분한다.
- 확인할 수 없는 정보는 사용자에게 요청한다.
- 미확정 사항을 임의로 결정하지 않는다.
- 불필요한 기술과 라이브러리를 도입하지 않는다.
- Docker, VMware, Terraform은 승인 전 도입하지 않는다.

## 4. 보안 원칙

- 최소 권한 원칙을 적용한다.
- 내외부 업무 영역의 접근 권한을 구분한다.
- 승인된 서비스 간 통신만 허용한다.
- VPN 인증과 애플리케이션 인증을 구분한다.
- 직원의 원장 DB 직접 접근을 제한한다.
- 원장 DB에는 승인된 내부 서비스만 접근한다.
- 망연계는 팀에서 승인한 통신 방식만 사용한다.

## 5. 민감정보 관리

- AWS 자격증명을 Git에 등록하지 않는다.
- VPN 개인키와 실제 접속 프로필을 등록하지 않는다.
- DB 비밀번호와 JWT 비밀키를 등록하지 않는다.
- 실제 고객 데이터를 사용하거나 등록하지 않는다.
- 민감 파일은 저장소 외부 또는 Git 제외를 확인한 승인된 로컬 전용 경로에 보관한다.
- 인프라의 로컬 전용 경로는 저장소 루트 기준 `infra/private/`, `infra/vpn/local/`, `infra/iam/local/`을 사용한다.
- 검토용 원본 PDF는 저장소 외부에 보관한다.
- 설정 예시에는 가상의 값만 사용한다.
- 민감정보를 출력하거나 문서에 기록하지 않는다.

## 6. AWS 및 Git 작업 제한

- 승인 없이 AWS 리소스를 생성하지 않는다.
- 예상 비용을 확인한 후 리소스를 생성한다.
- 사용자 승인 없이 commit, push, merge 하지 않는다.
- 기존 파일을 임의로 삭제하거나 이동하지 않는다.
- 사용자의 기존 변경사항을 되돌리지 않는다.

## 7. 사용자 학습 원칙

- 사용자가 직접 수행할 수 있는 작업은 자동화하지 않는다.
- AWS 콘솔 설정은 사용자가 직접 진행한다.
- Linux 및 Git 명령어의 역할을 설명한다.
- 구현 전 구조와 동작 원리를 설명한다.
- 어려운 구현과 오류 분석은 Codex가 지원한다.

## 8. 작업 완료 보고

작업 완료 후 다음 내용을 한국어로 보고한다.

1. 작업 ID 및 작업 목적
2. 생성하거나 변경한 파일
3. 구현 내용과 동작 원리
4. 실제 테스트 방법 및 결과
5. 기존 팀원 코드 변경 여부
6. 미해결 사항 및 위험 요소
7. 사용자가 이해해야 할 핵심 개념
8. 다음 단계 진행 가능 여부

실제 테스트하지 않은 기능은 완료 처리하지 않는다.
승인된 작업이 끝나면 검토 대기 상태로 종료한다.
